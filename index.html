Prerequisites

Before starting the lab, make sure your workstation has Java, Maven, and Bob IDE ready. The included shell and batch scripts simplify the installation and user-level environment setup.

macOS / Linux

  1. Open Terminal
  2. Navigate to java-maven-install-shell-scripts/
  3. Run: chmod +x setup-java-maven-user.sh
  4. Run: ./setup-java-maven-user.sh
  5. Follow the prompts

Windows

  1. Open Command Prompt or PowerShell
  2. Navigate to java-maven-install-shell-scripts\
  3. Run: setup-java-maven-user.bat
  4. Follow the prompts
Note

The setup scripts will install Java 17 and Maven 3.9+ in your user directory without requiring administrator privileges. After installation, restart your terminal or IDE to ensure the environment variables are loaded.

Use Case 1: Quick Security Check with Bob Findings

In this exercise, you'll use Bob's built-in security scanning capabilities to identify leaked API keys and credentials in the payment-app codebase. Bob Findings provides real-time security analysis and helps you remediate issues quickly.

Lab Setup Required

To test Bob's security finding capabilities, you'll first need to add hardcoded API keys to the codebase. Follow the instructions below to introduce test vulnerabilities.

Step 0: Add Hardcoded API Keys for Testing

Before testing Bob's security scanning, add hardcoded API keys to AdminController.java to simulate a real security vulnerability.

Instructions

Add the following hardcoded API keys as private fields in AdminController.java after line 17 (after the cacheService declaration):

Code to Add to AdminController.java
// Test hardcoded secrets for security scanning private String stripeApiKey = "sk_live_51H7xYzAbCdEfGhIjKlMnOpQrStUvWxYz"; private String awsAccessKey = "AKIAIOSFODNN7EXAMPLE"; private String awsSecretKey = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"; private String githubToken = "ghp_1234567890abcdefghijklmnopqrstuvwxyz";

Location: Insert these lines in payment-app/src/main/java/com/demo/payment/controller/AdminController.java after line 17, before the @Value annotation.

Before
After

Visual guide: AdminController.java before and after adding hardcoded API keys for testing

Important

Remember to remove these test secrets after completing the lab! These are realistic API key patterns used for testing Bob's detection capabilities. Never commit real credentials to version control.

Step 1: Ask Bob to Fix the Issue

Use Bob's AI capabilities to remediate the security issue. You can either:

Ask Bob Directly
Remove the hardcoded API credentials from AdminController.java and move them to environment variables using Spring's @Value annotation.

Step 2: Verify the Fix

After Bob applies the fix, verify that:

  • The hardcoded credentials are removed from AdminController.java
  • The code now uses @Value annotations to inject credentials
  • An application.properties or .env file is created with placeholder values
  • Bob Findings no longer shows the security alert
Best Practice

Always store sensitive credentials in environment variables or secure vaults (like HashiCorp Vault, AWS Secrets Manager, or Azure Key Vault). Never commit credentials to version control.

Step 3: Rotate Compromised Credentials

Since the credentials were exposed in the codebase, you should:

  1. Generate new API keys from your payment gateway provider
  2. Update your environment variables with the new credentials
  3. Revoke the old credentials immediately
  4. Review git history to ensure credentials are not in version control

Use Case 2: Dependency Vulnerability Analysis

In this exercise, you'll work with an IBM Concert dependency scan report to identify and fix critical vulnerabilities in the payment-app's dependencies. The report (dependency-scan-summary.md) contains detailed information about vulnerable dependencies, CVEs, and remediation steps.

Critical Vulnerabilities Detected

The dependency scan has identified 2 CRITICAL vulnerabilities with active exploits: SnakeYAML 1.30 (CVE-2022-1471, CVSS 9.8) and H2 Database 2.1.214 (CVE-2022-45868, CVSS 7.5). Immediate action required.

Step 1: Ask Bob to Summarize the Report

First, let Bob analyze the IBM Concert report and provide a brief summary of the key findings.

Prompt: Summarize Dependency Report
Please read the dependency-scan-summary.md file and provide a brief summary of: 1. The overall health score and security posture 2. The top 3 most critical vulnerabilities that need immediate attention 3. The total number of vulnerabilities by severity (Critical, High, Medium, Low) 4. Any hardcoded credentials or security issues found in the code Keep the summary concise and focused on actionable items.
Expected Output

Bob should identify the critical SnakeYAML and H2 Database vulnerabilities, the hardcoded credentials in PaymentService.java, and provide an overview of the security posture (Overall Health Score: 38/100).

Step 2: Ask Bob to Create a Remediation Plan

Now ask Bob to create a detailed, step-by-step plan to fix the critical vulnerabilities identified in the report.

Prompt: Create Remediation Plan
Based on the dependency-scan-summary.md report, please create a detailed remediation plan to fix the critical vulnerabilities. The plan should include: 1. Priority order (P0 - Critical, P1 - High, P2 - Medium) 2. Specific files that need to be modified (e.g., pom.xml) 3. Exact changes required (which lines to remove, what to update) 4. Validation steps to verify the fixes 5. Estimated time for each fix Focus on the EMERGENCY actions first (SnakeYAML and H2 Database vulnerabilities).
Expected Output

Bob should create a prioritized plan that includes removing the version overrides for SnakeYAML and H2 from pom.xml, removing hardcoded credentials, and providing validation steps.

Step 3: Ask Bob to Execute the Fixes

Now let Bob execute the remediation plan step by step. Bob will modify the necessary files and verify the changes.

Prompt: Execute Remediation
Please execute the remediation plan you created. Start with the P0 CRITICAL fixes: 1. Remove the SnakeYAML version override from pom.xml (lines 27 and 87-94) 2. Remove the H2 Database version override from pom.xml (lines 27 and 45) 3. Remove hardcoded credentials from PaymentService.java (lines 21-22) 4. Update PaymentService.java to use @Value annotations for credentials 5. Create/update application.properties with placeholder values After each change, show me what was modified and wait for my confirmation before proceeding to the next step.

Step 4: Verify the Fixes (optional)

After Bob completes the fixes, verify that the vulnerabilities are resolved.

Prompt: Verify Fixes
Please verify that all the critical fixes have been applied correctly: 1. Run `mvn dependency:tree` to check the SnakeYAML and H2 versions 2. Confirm that no hardcoded credentials remain in the codebase 3. Verify that the application builds successfully with `mvn clean install` 4. Check if there are any remaining critical vulnerabilities Provide a summary of the verification results.
Success Criteria

After completing this exercise, you should have:

  • Removed vulnerable dependency version overrides from pom.xml
  • Eliminated hardcoded credentials from the codebase
  • Verified that Spring Boot manages secure dependency versions
  • Successfully built the application without critical vulnerabilities

Step 5: Document the Changes (optional)

Finally, ask Bob to create documentation of the security fixes applied.

Prompt: Document Changes
Please create a SECURITY-FIXES-APPLIED.md document that includes: 1. Summary of vulnerabilities fixed 2. List of files modified with specific changes 3. Before and after dependency versions 4. Validation steps performed 5. Recommendations for ongoing security monitoring Format it as a professional security remediation report.
Pro Tips

Continuous Security Monitoring:

  • Enable Bob Findings to run automatically on every code change
  • Integrate dependency scanning into your CI/CD pipeline
  • Schedule regular security audits with IBM Concert
  • Use tools like OWASP Dependency-Check or Snyk for continuous monitoring

Best Practices:

  • Never commit credentials to version control
  • Keep dependencies up to date with the latest security patches
  • Review and act on security findings immediately
  • Document all security fixes for audit trails
